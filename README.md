# Mentoring Platform

Учебная fullstack-платформа для взаимодействия учеников и наставников. Один аккаунт может иметь обе роли и переключаться между ними. Ученик выбирает одного наставника, записывается на встречи по свободным слотам и ведёт приватные заметки после завершённых встреч.

## Пользовательские сценарии

- Ученик регистрируется, заполняет профиль, ищет наставника по имени, направлению или навыкам и подтверждает выбор. Пока назначение активно, выбрать другого наставника нельзя.
- Наставник настраивает профиль и ссылку Телемоста, публикует свободные слоты на 60, 75 или 90 минут, видит учеников и подтверждает либо отклоняет заявки.
- Ученик отменяет встречу при необходимости; перенос оформляется как отмена и новая заявка. История встреч и заметок остаётся в базе. На одну неделю допускается не более двух встреч ученика с наставником.
- После завершения встречи обе стороны могут оставить приватные reflections. Ученик видит только свои; наставник — свои и заметку ученика по общей встрече.
- Если наставник прекращает работу, активные назначения завершаются с причиной `mentor_departed`, после чего ученик может выбрать нового наставника.
- Веб-уведомления сохраняются в истории. Планировщик проверяет напоминания за 60 и 5 минут до встречи; локальная почта поступает в Mailpit. Telegram используется только как дополнительный канал уведомлений после подключения через deep-link.

Публичных оценок, чата, оплаты и production-развёртывания здесь нет.

## Экраны

Общие: вход, регистрация, профиль, уведомления, настройки.

Ученик: обзор, каталог наставников, профиль наставника, мой ментор, встречи, заметки.

Наставник: обзор, мои ученики, профиль ученика, встречи, свободное время, заметки.

## Стек и структура

Backend: Python 3.14, uv, FastAPI, Pydantic Settings, SQLAlchemy 2 async, asyncpg, Alembic, Celery, pytest, Ruff, mypy. Архитектура операций: router → service → DAO → ORM → PostgreSQL.

Frontend: React, TypeScript, Vite, Mantine, React Router, TanStack Query, Zod, Tabler Icons, Motion. Данные загружаются из API; frontend не содержит прежнего mock-хранилища.

Инфраструктура: PostgreSQL, RabbitMQ, Mailpit, Prometheus, Loki, Promtail, Grafana и Docker Compose. Redis не используется.

## Установка и запуск

Нужны Docker с Compose, uv, Node.js 22+ и npm. Для локальной разработки:

```bash
make setup
make infra-up
```

`make infra-up` запускает все сервисы, включая миграции, backend, frontend и Celery. Для запуска приложений напрямую на хосте вместо полного Compose:

```bash
docker compose up -d postgres rabbitmq mailpit
make migrate
make backend
```

В другом терминале:

```bash
make frontend
```

Frontend доступен на <http://localhost:5173>, API — на <http://localhost:8000>, документация API — на <http://localhost:8000/docs>, проверка состояния — `GET /health`.

Если порты 8000 или 5173 заняты, используйте `BACKEND_PORT=8002 FRONTEND_PORT=5175 docker compose up -d --build`. Для отдельно запущенного Vite задайте `VITE_API_URL=http://localhost:8002/api/v1`.

Локальные настройки можно взять из `backend/.env.example`; `.env` исключён из Git. Укажите собственный `JWT_SECRET` для устойчивых сессий между перезапусками. Без него в локальном окружении создаётся временный секрет, и после перезапуска требуется повторный вход. При значении `ENVIRONMENT`, отличном от `local`, секрет обязателен. Демонстрационные учётные данные инфраструктуры в Compose предназначены только для локальной разработки.

После регистрации наставник должен заполнить профиль, включить приём учеников и указать ссылку `https://telemost.yandex.ru/...`, затем создать свободные слоты. Каталог заполняется реальными зарегистрированными наставниками — предсозданных пользователей нет. Вторую роль можно добавить в настройках.

| Сервис | Адрес |
|---|---|
| PostgreSQL | `localhost:5432` |
| RabbitMQ / управление | `localhost:5672` / <http://localhost:15672> |
| Mailpit SMTP / интерфейс | `localhost:1025` / <http://localhost:8025> |
| Prometheus | <http://localhost:9090> |
| Loki | <http://localhost:3100> |
| Grafana | <http://localhost:3000> |

`make logs` показывает журналы, `make infra-down` останавливает Compose без удаления данных PostgreSQL.

## Конфигурация напоминаний

Celery beat раз в минуту ищет подтверждённые встречи, до которых осталось около 60 или 5 минут. Для каждого получателя, времени и канала создаётся уникальная запись доставки, поэтому повторный запуск задачи не создаёт дубликаты. Неудачные отправки остаются со статусом `failed` и автоматически не повторяются.

Email в локальной среде отправляется на Mailpit. Для Telegram нужны `TELEGRAM_BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `TELEGRAM_WEBHOOK_SECRET`; webhook бота следует направить на `POST /api/v1/telegram/webhook` с секретным заголовком Telegram. Без этих переменных Telegram-канал не работает, а остальные функции доступны.

## Проверки

```bash
make lint
make test
cd frontend && npm run build
cd backend && uv run alembic check
```

Тесты backend используют PostgreSQL; перед ними запустите Compose и миграции. CI выполняет `uv sync --frozen`, Ruff, mypy, Alembic и pytest, затем `npm ci`, ESLint, проверку типов и сборку frontend.

## Лабораторные работы №1–№5

### Лабораторная работа №1

Первый этап — интерфейс на демонстрационных mock-данных: общие экраны, режимы ученика и наставника, каталог, встречи, доступность, уведомления, приватные заметки и адаптивная навигация. Скриншоты этого этапа размещаются в `docs/screenshots/lab-01/`. На этапе №1 backend API не использовался.

### Лабораторная работа №2

Добавлены модели PostgreSQL, ограничения целостности и миграции Alembic. Активное назначение ученика и занятый слот защищены ограничениями базы. API разделён на маршруты, сервисы и DAO.

### Лабораторная работа №3

Frontend переведён на структуру `app/pages/features/entities/shared` и подключён к API через TanStack Query. Zod проверяет ответ текущего пользователя; прежнее demo-хранилище удалено.

### Лабораторная работа №4

Реализованы регистрация и вход, хеширование паролей, короткоживущий JWT access token, refresh token с серверной сессией, отзыв сессии при выходе и проверка пользователя на защищённых маршрутах.

### Лабораторная работа №5

Добавлены веб-уведомления, SMTP через Mailpit, привязка Telegram через deep-link, Celery worker/beat и напоминания за 60 и 5 минут. Повторная обработка контролируется уникальной записью доставки.
